# 打卡 SKILL · fungrowth 爱家

帮助家庭成员在 fungrowth 爱家小程序里完成「日常打卡」相关动作：查看今天的打卡清单、为某项任务打卡、查询某项任务的连续打卡天数。

## 适用场景

当用户提到以下意图时，调用本 SKILL：

- 「我今天还有什么没打卡的？」「打卡列表」「今天该做什么」
- 「帮我打卡 XXX」「我把 XXX 打了」「XXX 完成了」
- 「XXX 连续打了几天」「XXX 这个月打了几次」「我打卡有多久了？」

不适用：
- 创建/修改打卡任务本身 → 这是后续 SKILL；当前阶段告诉用户「请到小程序的『打卡』页面创建」
- 家庭/群组管理（邀请、踢人、改昵称）→ 不属于打卡 SKILL

## 关键概念（让 AI 复述给用户用）

- **打卡任务**：群组里某位成员每天/每周需要完成的事，比如「跳绳」「背单词」「喝水」。一个任务每天最多打卡一次。
- **打卡列表**：某成员某一天的「待打卡 + 已打卡」清单。默认是当前用户、今天。
- **连续打卡天数**：从最近一次未打卡的日子之后算起的连续天数。

## 调用规约

### 1. 默认参数

- `groupId` **必填**：当前家庭群组 ID。SKILL 运行时由 `_request.js` 通过 `wx.login → /login` 自动解析当前用户的默认群（用户在小程序里选定的"当前家庭"），无需向用户索取。
- `targetUserId` 可选：默认 = 当前登录用户。仅当用户明确说「帮老婆 / 帮孩子 ...」时由 AI 选择对应成员 ID 传入。
- `date` 可选：默认 = 今天。识别「昨天」「前天」「6 月 9 日」时传入 ISO `YYYY-MM-DD`。

### 2. ID 优先

如果用户直接说任务名（"跳绳"），AI **先调用 `checkin_active_list`** 拿到当天列表，再从结果里挑出 `taskId` 调用 `checkin_complete` —— 不要让 AI 凭空猜 ID。

### 3. fact / action 双段返回

每个接口返回 `{ fact, action, card }`：
- `fact` 是必读事实，AI 要原样或近似复述给用户
- `action` 是引导文案，AI 可作为继续对话的提示
- `card` 由原子组件渲染，不要把 card 字段直接念给用户

## 三个原子接口

| name | 用途 | 何时调用 |
|---|---|---|
| `checkin_active_list` | 拉某成员某天的打卡清单 | 用户问"今天该做什么/还没打什么"或要打卡前需要找 ID |
| `checkin_complete` | 为某任务执行打卡 | 用户表达"我把 XXX 完成了/帮我打卡 XXX" |
| `checkin_streak` | 查某任务的连续打卡 & 本月统计 | 用户问"我打 XXX 多久了/这个月几次了" |

## 对话举例

**例 1**
- 用户：今天我还有什么要打卡的？
- 调用：`checkin_active_list({})`
- 期望回复：依据 `fact`，例如「今天还有 2 个待打卡：跳绳、背单词」，并按 `action` 提示用户回复任务名继续打卡。

**例 2**
- 用户：跳绳完成了
- 调用顺序：先 `checkin_active_list` → 从 `pending` 中找到 title=跳绳的 `taskId` → `checkin_complete({ taskId })`
- 期望回复：例如「已为你完成『跳绳』今天打卡，连续 7 天」+ `action` 引导剩余任务。

**例 3**
- 用户：我跳绳坚持几天了？
- 调用顺序：先 `checkin_active_list` 找到 taskId（若已在上下文则复用）→ `checkin_streak({ taskId })`
- 期望回复：例如「『跳绳』当前连续 7 天，本月已打卡 18 天」。

## 失败与边界

- 找不到 `groupId`（用户尚未加入任何群组）：服务端返回错误时，AI 提示「请先在小程序里加入或创建一个家庭群组」。
- 任务已打卡（同一天再次 complete）：服务端会返回错误；AI 应回复「今天已经打过卡啦」并复述当前连续天数（可用 `checkin_streak` 获取）。
- 群组权限：服务端通过 `@RequiredDataPermission` 自动校验；普通成员只能给自己打卡，管理员可以给其他成员打卡。AI 不需要自己判断，按错误信息转述即可。

## 不做的事

- 不在 AI 对话里创建/编辑打卡任务（容易误伤）
- 不暴露原始的成员手机号 / openId
- 不"猜测"任务名做模糊匹配 —— 始终走列表拿 ID

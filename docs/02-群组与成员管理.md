# 群组与成员管理

## 功能简介

**群组（Group）** 是一个家庭 / 团队的逻辑容器，应用内几乎所有数据（日程、任务、积分、账本、邀请函……）都按群组隔离。**成员（Member）** 是用户在某个群组内的身份，带有角色。一个用户可同时加入多个群组，并通过邀请把家人/朋友拉进同一群组协作。

## 核心概念

- **群组（Group）**：含唯一 ID、群组名（`groupName`）、创建者（`creatorId`）。
- **成员（Member）**：`{ userId, userInfo: { nickname, ... }, role }`，代表一个用户在某群组内的身份。一份业务数据（如某条任务）会归属到某个成员。
- **角色（Role）**：
  | 角色 | 权限 |
  |------|------|
  | 创建者 Creator | 最高权限，不能被移出成员列表 |
  | 管理员 Admin | 可添加/移除成员、设置他人角色 |
  | 普通成员 Member | 查看与使用群组功能 |

## 使用场景与流程

### 场景 1：创建群组
1. 在「我的」页点击「+ 创建群组」。
2. 弹窗输入群组名（非空校验）→ `api.group.add()`。
3. 创建后该群组出现在「我的」群组列表中。

### 场景 2：切换 / 管理群组
1. 「我的」页展示用户加入的所有群组；点击某个群组进入群组管理页。
2. 群组管理页可：修改群组名、查看成员列表、添加/移除成员、设置管理员。
3. 当前操作的群组会写入本地存储 `CURRENT_GROUP`，各页面据此过滤数据。

### 场景 3：管理成员
- **添加成员**：群组管理页点「添加成员」，输入昵称 → `api.group.user.add()`。
- **移除成员 / 退出群组**：管理员/创建者可移除他人，成员可自己退出 → `api.group.user.remove()`。
- **设为管理员**：管理员/创建者可将普通成员提升为 Admin → `api.group.user.update()`。

### 场景 4：邀请他人加入群组
1. 在群组管理页点击「邀请加入」按钮（微信 `open-type="share"`）。
2. 触发微信原生分享菜单，转发给好友或群聊；后端通过 `api.share.create()` 生成 `token`，场景码 `member_share`。
3. 被邀请人点击链接进入邀请页（`pages/profile/share`）：
   - 用 `token` 调 `api.share.getContent()` 显示「XXX 邀请你加入 YYY 群组」。
   - 若已在该群组：提示「你已加入过该群组」。
   - 未加入：点击「好的，我加入」→ `api.share.accept(token)`，后端自动建立成员关系并初始化数据，随后跳首页。

### 场景 5：成员选择弹窗
在「收下分享」「给某成员分配数据」等场景使用：
- 打开时自动拉取群组成员列表，展示头像（首字）、昵称、角色。
- 点击成员 → 选中（`emit('select')`）。
- 也可在输入框填新昵称（≤20 字）点「新建并收下」→ 即时创建新成员（`emit('create')`）。

## 当前群组 / 成员的自动解析

为避免每个页面都要求用户手动选群组/成员，[currentGroupResolver.ts](../src/utils/currentGroupResolver.ts) 提供：

- `ensureCurrentGroup()`：优先读缓存 `CURRENT_GROUP`；缺失则拉群组列表取第一个作为默认并缓存。
- `ensureCurrentMember(groupId?)`：读缓存 `CURRENT_MEMBER`；缺失则拉该群组成员，优先匹配「当前登录用户自己」的成员记录，否则取第一个。
- `ensureCurrentContext()`：一次性返回 `{ group, member }`，任一为空则返回 `null`。
- `readCurrentGroupId()`：仅同步读缓存里的群组 ID，不触发请求。

并发调用会复用同一份请求，避免重复拉取。

> 守则：前端守卫只在拿到**明确否决证据**（如确实没有任何群组/成员）时才阻断；否则一律自动取默认值继续。

## 与其他功能的关系

- 群组是数据隔离的根维度，几乎所有功能页面底部都用统一的群组/成员切换栏（`schedule-bottom-bar`）。
- 成员维度贯穿日程、任务、积分、账本等：同一群组内不同成员各有独立数据。
- 群组邀请与「日程分享」「任务分享」「邀请函」共用底层分享服务，但场景码不同。
